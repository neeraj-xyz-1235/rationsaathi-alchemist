# RationSaathi — Team Plan (READ THIS FIRST)

Problem: P-01 RationSaathi (full statement + G's summary + original frontend notes: context.txt)

What we build in one sentence:
  The user enters explicit entitlement rules, family size, and what they actually received (with
  evidence). We show expected vs received vs difference, line by line, with the evidence attached,
  in neutral language, in English / Hindi / Marathi.

Other plan files:
  plan_backend.txt     API contract (everyone reads §2), engine rules, receipt parser   — G + N
  plan_db_schema.txt   database choice + tables                                         — G
  plan_deployment.txt  repo layout, git workflow, CI, Vercel/Render/Neon, demo checklist — N
  plan_frontend.txt    M/A split, state shape, API client, screen tasks                  — M + A

Time assumption: about 6 hours of build time (context.txt plans for 5–6 hours). If we have
longer, stretch Phase 1–2. Don't add features.

One change from G's summary: **the discrepancy label (shortfall / late / unrecorded / unclear) is
decided by fixed rules in Python, not by AI.** The brief requires transparent classification, and
"the AI decided it's a shortfall" is hard to defend in front of judges. AI does only one job:
turning messy receipt text into suggested fields.

One change from the frontend notes in context.txt: **the calculator lives in the backend only.**
The frontend does no arithmetic. It shows what /api/calculate returns, which gives us one source
of truth. Section 7 of context.txt still describes the math correctly. Only its location changes.


## 2. Architecture

    Browser — React on Vercel. It calls /api/* on its OWN domain; Vercel forwards to Render.
      | keeps the whole "case" in React state (+ localStorage draft) while the user edits
      |
      |-- /api/auth/* ---------------> FastAPI --> users + sessions (argon2id, HttpOnly cookie, rate limits)
      |-- /api/shops/nearby ---------> FastAPI --> placeholder: "planned", [] (map = OSM tiles in browser)
      |
      |-- POST /api/receipt/parse --> FastAPI --> Claude: segments the text into fields
      |                                      \--> regex fallback (no key / timeout / bad output)
      |                                      --> Python normalises numbers + dates (no AI)
      |                                      <-- SUGGESTIONS only; the user must confirm
      |
      |-- POST /api/calculate ------> FastAPI --> engine/ (units, calculator, classifier)
      |                                          pure Python, integer base units, NO AI
      |
      \-- /api/cases, /api/reports --> FastAPI --> Postgres (Neon): saved cases + report snapshots


## 3. Golden rules (put these on the whiteboard)

1. AI only suggests. Only records with status "confirmed" go into the math.
2. All math lives in backend/app/engine. Quantities become integers in grams, ml or pieces
   (Decimal → int). No floats anywhere.
3. Apply only the rules the user entered. If an item has no rule, it is "unclear". We never
   guess a rule.
4. Never invent evidence. No receipt means the report says "no receipt provided".
5. Use neutral words only. Banned in any UI or report text: fraud, theft, steal/stole, cheat,
   scam, corrupt, embezzle, illegal, black market, guilty (plus the Hindi and Marathi
   equivalents listed in plan_deployment.txt). CI fails if one of these appears.
   Write disclaimers without them too: "The reason for this difference has not been established."
6. The backend returns codes and numbers. The frontend turns them into sentences in en/hi/mr.
7. Differences are always shown with their sign and explained. Receiving MORE than expected is
   not an error either.

## 6. Demo scenario (used in mocks, tests and the live demo)

Use a period that has ALREADY ENDED, so "shortfall" is allowed. If the period is still running,
the engine correctly says "unclear: period not ended", which makes a weaker demo.

  Members: 4
  Period:  2026-09-01 to 2026-09-30
  Rules:   Rice  — 5 kg per member
           Wheat — 2.5 kg per member      (shows exact decimal math)
  Records:
    d1  Rice   8 kg  2026-09-03  pasted text "Rice 8kg recvd 03/09 Rcpt#101" → AI suggestion → confirmed
    d2  Rice   6 kg  2026-09-20  Receipt #145, typed manually
    d3  Wheat 10 kg  2026-09-05  note only: "Collected at shop, no receipt given"
  Optional: paste "Sugar 1kg 12/09". There is no Sugar rule, so it shows as unclear and is not counted.

  Expected result:
    Rice:  4 × 5 kg = 20 kg | 8 kg + 6 kg = 14 kg | 20 kg − 14 kg = 6 kg   → shortfall
    Wheat: 4 × 2.5 kg = 10 kg | 10 kg | 10 kg − 10 kg = 0 kg                → no difference
    Evidence: 2 records with a receipt number, 1 with pasted receipt text, 1 note-only

  Report sentence (Rice):
    "Confirmed records for Rice total 14 kg against an expected entitlement of 20 kg for
     1–30 Sep 2026, a difference of 6 kg. The reason for this difference has not been established."

  Demo talking points: (1) the AI suggestion needs user confirmation; (2) the date "03/09" is
  ambiguous and gets resolved using the period, with the reason shown; (3) line-by-line math;
  (4) evidence for every line; (5) switch to Hindi/Marathi; (6) neutral wording; (7) print.
